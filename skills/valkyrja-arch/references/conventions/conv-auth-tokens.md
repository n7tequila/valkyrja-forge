# 认证令牌约定（服务端侧）

> 前端侧的完整生命周期（单飞刷新、队列 reject、logout 顺序）在
> conv-frontend-api-layer——本条管服务端与协议层，两条合用构成闭环。

## 协议基线

- 承载：`Authorization: Bearer <token>`。
- **401 与 403 严格分工**：401 = 未认证/令牌无效或过期（该重新登录）；
  403 = 已认证但无权限（重新登录也没用）。混用会让前端刷新逻辑
  在无权限场景死循环刷新。
- **豁免认证的路由显式白名单**（登录、健康检查、公开静态资源）——
  在路由配置一处声明，禁止散落在各 handler 里自行放行。

## 双令牌生命周期

- access 短寿（分钟级）+ refresh 长寿（天级）；业务接口只认 access。
- **refresh 只能用于刷新接口**，不得当 access 用；刷新时轮换 refresh
  （旧 refresh 立即失效），被盗令牌的可用窗口收敛到单次。
- **logout 必须服务端吊销 refresh**——只清客户端本地，refresh 仍有效，
  是真实安全缺陷（详见前端约定的反模式表）。
- 服务端维护吊销能力（黑名单/版本号/会话表任选），
  纯无状态 JWT + 无吊销通道 = 无法应对令牌泄露，禁止作为默认方案。

## 载荷纪律

- JWT 载荷只放：主体 ID、角色/权限摘要、过期时间、必要的会话标识。
  **禁止放个人敏感信息**（手机号、证件号）——JWT 是 base64 不是加密。
- 权限判定以服务端为准；令牌里的角色只是缓存，
  关键操作（行级权限）仍按聚合根守卫校验（见 conv-java-ddd 规则 5）。

## 安全细节

- 登录失败响应不区分「用户不存在」与「密码错误」（防账号枚举）；
  对应 API 层规则：登录场景 USER_NOT_FOUND 回 401 不回 404。
- 登录接口必须限流；失败次数阈值触发冷却或验证挑战。
- 令牌签名密钥走环境变量/密钥管理，**启动时校验存在，缺失 fail-fast**——
  禁止代码内 fallback 默认密钥（"开发方便"的默认密钥必然进生产）。

## 采纳时须绑定的项目参数

- access / refresh 有效期与刷新接口路径
- 吊销机制选型（黑名单 / 版本号 / 会话表）
- 豁免路由清单的声明位置
