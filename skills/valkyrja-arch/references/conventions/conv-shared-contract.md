# 共享接口契约的文档约定

> 适用对象：**被两个及以上变更/模块消费的接口形状**（数据包结构、事件载荷、
> 文件格式、进程间协议）。单个模块内部的形状不需要契约文档。

## 契约文档四要素（缺一不完整）

1. **形状**：字段表（名称/类型/必填/语义/取值边界）；机器要解析的部分给精确格式
2. **语义**：字段何时出现、由谁填、消费方如何解释
3. **兼容规则**：什么变更破坏、什么不破坏；消费方对未知字段的姿态
4. **Changelog**：每个版本的变更与破坏性标注

## 版本规则

- 版本 = **递增整数**，消费方引用格式 `契约名@版本`
- 默认兼容姿态：**新增可选字段不破坏**（版本可不动或 +1 标注 additive）；
  删除字段、改语义、改类型 = **破坏性**，必须版本 +1 并在 Changelog 标注
- 消费方默认**忽略未知字段**——为生产方留出 additive 演进空间
- 生产方做破坏性变更前，**必须现算消费方清单**并逐个确认迁移路径
  （消费方清单现算不落盘——落盘即成漂移的缓存）

## 反模式

| 反模式 | 后果 |
|---|---|
| 契约只活在某一方的实现/设计文档里 | 另一方看不见，变更即断裂 |
| 用日期或 semver 给契约文档做版本 | 引用冗长、兼容语义并不适用 |
| 消费方对未知字段报错 | 生产方任何 additive 演进都被迫成为破坏性 |
| 维护"消费方清单"字段 | 清单必然漂移，误导破坏性评估 |
