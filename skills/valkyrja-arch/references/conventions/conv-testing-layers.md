# 测试分层约定

> 摘编自 ECC（MIT，版权声明见本目录 NOTICE.md，随本 catalog 分发），按本 catalog 风格改写并加入
> 取舍性说明。框架级细则见各 stack 条目（如 conv-spring-testing）。

## 三层结构

| 层 | 测什么 | 特征 |
|---|---|---|
| 单元 | 纯函数、工具、单组件逻辑 | 快、无外部依赖、数量最多 |
| 集成 | API 端点、数据库操作、模块协作 | 真依赖（容器化），覆盖装配与翻译层 |
| E2E | 关键用户流程 | 少而准，只保护「用户真正走的路」 |

- 三层**都要有**；用上层测试替代下层（全靠 E2E）或反之（全靠单元）都是失衡。
- 层间职责不重复：单元测过的逻辑分支不在 E2E 重演，E2E 只走代表性主路径。

## 结构与命名

- **AAA 结构**（Arrange-Act-Assert），三段留白分隔，一个测试一个行为断言主题。
- **测试名描述行为而非方法名**：`returns empty list when no match`
  优于 `testQuery2`——失败清单本身就该是行为规格说明。
- 失败断言优先于成功断言的丰富度：错误路径、边界值、空集合是回归高发区。

## 覆盖率的正确用法

- 覆盖率目标（如 80%）是**护栏不是目的**——它挡住"整块逻辑完全无测试"的滑坡，
  但 100% 覆盖 + 空洞断言比 70% 覆盖 + 严断言更危险。
- 关键路径（资金、认证、安全、核心业务规则）要求接近全覆盖 + 变异级断言；
  展示型代码允许低覆盖，由视觉/E2E 兜底。
- **修 bug 先写复现测试**（红）再修（绿）——没有复现测试的修复无法防回归。

## 纪律

- 测试失败改实现不改测试，除非能论证测试本身错了。
- 测试间零共享可变状态；顺序无关；可单跑。
- Mock 只 mock 边界（外部服务、时钟、随机），不 mock 被测物自己的邻居——
  过度 mock 的绿 = 装配问题的盲区（见 conv-spring-testing §6 的 CI 陷阱）。

## 采纳时须绑定的项目参数

- 各层覆盖率护栏值与关键路径清单
- E2E 框架与运行环境
