# Web 本地存储选型与敏感数据落盘约定

## 选型准则

| 机制 | 适用 | 不适用 |
|---|---|---|
| localStorage | 极小量、非敏感、同步读写可接受的标志位/偏好 | 任何列表型/增长型数据；敏感数据 |
| IndexedDB | 结构化队列、可增长数据、需事务与索引 | 极简单的单值 |
| Cache Storage（SW 配套） | 静态资源缓存 | **业务数据存储**（它是资源缓存不是数据库） |
| 内存 | 会话内临时状态 | 任何需要跨刷新存活的数据 |

**平台中立注意**：若应用被要求能脱离 Service Worker 运行，业务数据一律不得
依赖 SW 生命周期内的任何存储；数据层与资源缓存层严格分离。

## 敏感数据落盘铁律

1. **加密后落盘**（Web Crypto，认证加密模式如 AES-GCM），明文不落任何存储
2. **密钥不硬编码**——随远端下发、支持轮换；密文条目**记录其密钥版本**，
   轮换后旧条目仍可解（直到按留存策略清除）
3. **留存上限显式**：每类敏感数据必须有 TTL 或"用完即删"策略，超期自动清除；
   没有留存策略的敏感数据落盘视为缺陷
4. **界面不可见明文**：不提供任何在 UI 上查看已落盘敏感明文的入口，
   包括调试页——调试信息只给条数/状态，不给内容
5. 删除用"物理删除"语义：完成使命的条目立即删除，不做软删除标记

## 实测先行

浏览器间配额、持久化保证、清理策略差异极大（且 Kiosk 常驻场景与普通浏览
行为不同）。**目标设备上的存储行为必须 spike 实测**后再定案：
配额、跨重启持久化、浏览器"存储压力清理"是否可豁免——纸面选型不作数。
