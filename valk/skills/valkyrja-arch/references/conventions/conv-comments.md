# 注释约定

## 一条判据

**注释只写代码自身表达不了的约束与原因（WHY / 不变量 / 陷阱），
不写代码正在做什么（WHAT）。** WHAT 该由命名与结构表达——
需要注释解释 WHAT 的代码，先改代码。

## 写注释前的五问

准备写注释时逐条自问，**任一条答"能"就改代码，不写注释**：

1. 换个更准的变量名能说清吗？
2. 换个更准的方法名能说清吗？
3. 抽成一个小函数能说清吗？
4. 用更强的类型（枚举 / 值对象 / 非空标注）能说清吗？
5. 理顺控制流（早返回 / 拆分支）能说清吗？

五问全否，才轮到写注释。**改进代码优先于解释烂代码**——注释是最后手段，
不是补救手段。典型反例：给 `if (status == 1)` 配一句「判断是否有效」，
正解是改成 `if (record.isValid())`，而不是把那句注释写得更详细。

## 该写的

| 类型 | 例子 |
|---|---|
| 不可见约束 | 「finally 清除是硬要求——线程池复用下不清除 = 上下文串号」 |
| 反直觉原因 | 「此处 catch Exception：POI 抛的是 RuntimeException 子类，不是 IOException」 |
| 外部契约锚点 | 「字段顺序与 content-package@1 对齐，勿调整」 |
| 刻意不做 | 「不做重试：上游已有幂等补传，这里重试会双写」 |
| 公共 API 文档注释 | 参数语义、边界值、异常条件（按栈的 docstring 惯例） |

## 选型理由归 ADEC，代码里只留锚点

**「为什么选 A 不选 B」是技术决策，写进 ADEC，不在代码注释里展开论证。**
代码侧留一行机读锚点：

```
// 依据: ADEC-<DOMAIN>-<NNN>
```

- 逐字前缀 `依据: ` 是机读协议的一部分——`trace` 的源码依据引用完整性检查按此
  扫描，能查出指向不存在或已 superseded 的决策。写成「参考」「见」「基于」
  一律扫不到，等于没标。**该标不标它不管，但标了就必须能解析**：要么用逐字
  前缀标对，要么别标。
- 论证写进注释的代价：ADEC 被 supersede 时注释不会跟着改，读者读到的是**已被
  推翻的理由**，且没有任何机制能发现——这正是锚点要机读、论证要留在 ADEC 的原因。
- 注释里可以留一句**结论**（约束是什么），论证过程不进代码。

## 复杂算法：块首写策略

- 一段算法在**入口处一条高密度注释**说清策略与不变量，正文零注释。
- 不做逐行翻译（`// 遍历 section`、`// 判断权限是否变化`）。逐行注释是把
  「读者看不懂这段代码」用增加阅读量的方式回避掉；真读不懂，该拆的是函数。

## 公共 API 文档注释

- 写**契约**：输入语义、返回语义、副作用、异常条件、特殊值、幂等性。
- **不写内部实现**——实现会变而契约不变，写了实现的文档注释必然漂移成谎话。
- 首句是一句能独立成立的完整摘要（多数 doc 工具只取首句做索引），
  不用「本方法用于……」开头凑字。
- 具体格式与必填标签按栈在项目参数里绑定，本层不规定。

## 禁止的

| 反模式 | 为什么 |
|---|---|
| 叙事注释（`// 遍历列表`） | 与代码同义反复，漂移后变误导 |
| 历史注释（`// 2026-08 从 X 改为 Y`） | 那是版本控制的职责 |
| 对话残留（`// 按评审意见修改`、`// 修复 bug`） | 面向一次性读者，合入即噪音 |
| 猜测性注释（`// 大概是`、`// 应该没问题`、`// 可能要处理`） | 把不确定性伪装成文档；真不确定就查清，或写成带触发条件的 TODO |
| 注释掉的代码 | 删。需要时从历史找 |
| 装饰性分隔横幅 | 结构该由文件拆分表达 |

## 维护纪律

- 改代码必须同步改其注释——**过期注释比没有注释更危险**（读者信注释不信代码）。
- TODO 必须带**可执行的触发条件或去向**（`TODO: content-package@2 落地后删除此兼容分支`）；
  裸 TODO 视为垃圾，review 应要求补全或删除。
- 注释密度跟随代码危险度，不追求覆盖率：陷阱密集处厚写，直白处零注释是常态。
- AI 生成代码同规则：**禁止生成"解释我为什么这么写给审阅者看"的注释**——
  那是对话内容，不是代码文档。同样禁止在注释里提及 AI、prompt、任务编号
  或生成过程，以及"之前/现在/已修复/已改为"式的自述。

## 采纳时须绑定的项目参数

- 各栈 docstring 格式（Javadoc / TSDoc / docstring 风格）
- 公共 API 文档注释的必填标签集，以及哪些可见性层级强制要求
- TODO 的追踪方式（是否要求关联 issue/backlog 条目）
