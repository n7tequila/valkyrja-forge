# 幂等标识约定

## 核心规则

1. **幂等键由客户端在动作发生时生成**（UUID v4），与动作数据一同持久化；
   重试、补传、断线重连**携带同一个键**，永不重新生成——重新生成即打破幂等。
2. **一个逻辑动作一个键。** 同一次用户提交无论经过多少次传输尝试都是一个键；
   不同动作（哪怕内容相同）必须不同键。
3. **服务端以键去重**，幂等窗口必须 ≥ 客户端的最大重试窗口
   （含离线队列的留存上限，否则超窗重传会产生重复记录）。
4. **键名从契约，不从习惯。** 字段叫什么由该接口的共享契约或外部权威
   （如产品需求已钉名）决定；本约定只管生成与携带的语义，不规定通用字段名。
5. 键随载荷落盘时，与其加密/留存策略一致——键本身不含业务语义，
   但可与记录关联，按记录同级保护。

## 反模式

| 反模式 | 后果 |
|---|---|
| 用时间戳做幂等键 | 同秒并发碰撞；客户端时钟不可信 |
| 用内容哈希做幂等键 | 两次独立但内容相同的动作被误判为重复 |
| 重试时重新生成键 | 服务端视为新动作，产生重复记录——幂等形同虚设 |
| 服务端幂等窗口 < 客户端重试窗口 | 超窗重传穿透去重 |

## 采纳时须绑定的项目参数

- 各写入口的幂等键**字段名**（从契约/外部权威取）
- 服务端幂等窗口时长（≥ 客户端最大重试窗口，写明推导）
