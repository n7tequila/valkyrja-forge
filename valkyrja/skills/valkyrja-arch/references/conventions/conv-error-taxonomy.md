# 错误分类与呈现约定

## 三轴分类

每个错误先按三轴定位，再查呈现表——不允许"遇到再说"式的临场处理：

| 轴 | 取值 |
|---|---|
| 来源 | 用户输入 / 环境（网络、设备、配额）/ 系统内部 |
| 可重试性 | 立即可重试 / 延后自动重试 / 不可重试 |
| 用户可见性 | 必须告知 / 静默处理 + 可查 / 完全静默（仅上报） |

## 呈现约定（用户侧）

| 类别 | 呈现 |
|---|---|
| 用户输入错误 | **就地提示**（字段旁/表单内），阻止提交，给出可行动的修正指引 |
| 环境错误（可自动恢复） | 静默排队/重试 + **非模态**状态提示；恢复后自动继续 |
| 环境错误（不可自动恢复） | 明确告知 + 提供人工出口（重试按钮/联系方式） |
| 系统内部错误 | 兜底文案（不暴露内部细节）+ 完整上报 |

**禁止**：静默吞掉任何错误；对面向公众的终端使用模态遮罩弹窗打断
（打断即会话终止风险）；把内部异常信息原样透给用户。

## 错误码约定（机器侧）

- 命名：`<MODULE>_<REASON>`，UPPER_SNAKE_CASE（如 `ORDER_RATE_LIMITED`）
- **禁止硬编码字符串字面量散落**——集中为常量/枚举，一处定义
- 分层映射模式（后端场景）：异常类型 → 状态码/错误码的映射**集中在一处**
  （全局 handler / 中间件），业务代码只抛语义异常不拼响应
- 业务失败与传输失败分离：业务规则拒绝 ≠ 请求失败，状态码与错误码分开表达

## 采纳时须绑定的项目参数

- 本项目的 MODULE 前缀清单
- 各呈现类别的具体交互组件（哪种提示条/哪个兜底页）
- 上报通道（接到哪个埋点/日志约定）
